# rutis 0.7.0

[中文](https://github.com/arcships/rutis/blob/v0.7.0/docs/releases/0.7.0.md) · [Migration guide](https://github.com/arcships/rutis/blob/v0.7.0/docs/migration-0.6-to-0.7.en.md)

0.7.0 brings the plugin control plane, language runtimes and networked nodes into one developer workflow. With `rutis-host`, TypeScript, JavaScript and Python authors can scaffold, check, run and reload plugins without writing a Rust host.

## Packages

These packages are versioned **0.7.0**. Publish the core first using its existing workflow, then publish the train:

| Registry | Packages |
| --- | --- |
| crates.io | `rutis`, `rutis-bridge`, `rutis-loader`, `rutis-host` |
| npm | `@arcships/rutis`, `@arcships/rutis-runtime`, `@arcships/rutis-host`, and four platform host packages |
| PyPI | `rutis`, `rutis-host` |
| GitHub | `rutis-host` binaries and SHA-256 checksums for Linux/macOS, x64/arm64 |

`rutis-cli`, the agent examples, `aimux-llm` and dylib tools retain their independent versions and are not published by this train. Their in-repository core dependencies are updated.

## Changes since 0.6.0

- **Typed plugins:** `TypedPlugin` and typed factories connect dependency types, runtime service keys and plugin assembly.
- **Plugin control plane:** layered configuration, dynamic edits, persistence, service catalogs, expressions, multiple plugin sources, volatile configuration and self-disposal through `rutis-loader`.
- **dsh and development channel:** includes, user layers and hot reload; `rutis-dev` adds state observation, temporary plugins and atomic replacement.
- **Native plugins:** macOS and Windows x64/MSVC loading, dependency checks before loading, and prebuilt SDK bundles for external plugin builds.
- **Language plugins:** JS/TS and Python leaf plugins, named runtimes, service sharing, lifecycle cleanup, cross-session references and module refresh.
- **Remote runtimes:** loader rows on other machines, controller leases, release and takeover.
- **Nodes:** shared connections, service imports/exports, hosted plugins, events, multi-hop calls and reconnection.
- **Transports:** local and inherited Unix sockets, in-memory channels, WebSocket with TLS, authentication and shared listeners.
- **Standalone host:** `rutis-host new`, `check`, `run` and `dev`, with matching Node/Python project templates.
- **Guides and validation:** Chinese/English role-based guides, channel/session/runtime/node conformance suites, and reconnect/process-lifecycle soak tests.

Typed plugins, the control plane, the development channel and macOS/Windows dylib support were already present in the `rutis-v0.6.1` tag.

## Compatibility

`rutis-interop` is folded into `rutis-bridge`. The npm SDK and runtime are now `@arcships/rutis` and `@arcships/rutis-runtime`. Existing users must migrate dependencies, imports, features and generated bindings using the [migration guide](https://github.com/arcships/rutis/blob/v0.7.0/docs/migration-0.6-to-0.7.en.md). Upgrade hosts and language runtimes together.

Package versions are separate from protocol versions: local sessions retain protocol 2; endpoint sessions use protocol 3. This version alignment does not change the plugin API marker. Rebuilding the dylib SDK with the new core changes its identity: rebuild the host and plugins together.

`rutis-host` and local language runtimes support Linux/macOS; use WSL on Windows. Native Windows dylib support does not imply native Windows host support. Node 24+ and Python 3.12+ are required.

## Getting started (after publication)

```bash
cargo add rutis@0.7
npx @arcships/rutis-host@0.7.0 new greeter --lang node
uvx --from rutis-host==0.7.0 rutis-host new greeter-py --lang python
```

Read the [developer guides](https://github.com/arcships/rutis/blob/v0.7.0/docs/guide/README.en.md) for plugins, embedding and networking.
