# rutis 0.7.0

[English](0.7.0.en.md) · [升级指南](../migration-0.6-to-0.7.md)

0.7.0 把插件控制面、多语言插件、远程运行时与节点互联整合为一套可直接使用的开发流程。`rutis-host` 让 TypeScript、JavaScript 和 Python 插件从创建项目到运行、检查和开发重载都不需要编写 Rust 宿主。

## 发布包

以下包版本均为 **0.7.0**，沿用现有流程先发布内核，再发布列车：

| 注册表 | 包 |
| --- | --- |
| crates.io | `rutis`、`rutis-bridge`、`rutis-loader`、`rutis-host` |
| npm | `@arcships/rutis`、`@arcships/rutis-runtime`、`@arcships/rutis-host`，以及四个平台的 host 包 |
| PyPI | `rutis`、`rutis-host` |
| GitHub | Linux / macOS，x64 / arm64 的 `rutis-host` 二进制与 SHA-256 校验文件 |

`rutis-cli`、agent 示例、`aimux-llm` 和 dylib 工具链继续使用各自版本，不属于本次注册表发布列车。仓库内它们对内核的依赖已更新。

## 从 0.6.0 起的主要变化

- **类型化插件**：`TypedPlugin` 与类型化工厂把依赖类型、运行时服务键和装配入口关联起来。
- **插件控制面**：`rutis-loader` 提供分层配置、动态增删改、持久化、服务目录、表达式和多种插件来源；支持 volatile 配置及插件自行卸载。
- **dsh 配置与开发通道**：配置 include、用户层和热重载；`rutis-dev` 支持观察状态、临时装载和原子替换。
- **原生插件工具链**：dylib 加载扩展到 macOS 和 Windows x64/MSVC，增加加载前依赖检查；SDK 构建包允许插件基于预构建 SDK 编译。
- **多语言插件**：JS/TS 与 Python 叶子插件、命名运行时、服务导入导出、生命周期清理、跨会话引用转发和模块刷新。
- **远程运行时**：可在其他机器的语言运行时中运行 loader 行，提供控制租约、释放和接管机制。
- **节点互联**：连接共享、服务导入导出、插件托管、事件转发、多跳调用及断线重连。
- **传输**：本地 Unix socket、继承 socket、内存通道、WebSocket，含 TLS、认证和共享监听器。
- **通用宿主**：`rutis-host new`、`check`、`run`、`dev`，以及匹配版本的 Node / Python 插件脚手架。
- **开发文档与验证**：中英文角色指南，通道、会话、运行时和节点一致性测试，重连与进程生命周期压力测试。

从 `rutis-v0.6.1` 升级时，类型化插件、控制面、开发通道以及 macOS/Windows dylib 支持已经包含在旧标签中。

## 升级与兼容

`rutis-interop` 合并进 `rutis-bridge`；npm 插件 SDK 与运行时拆分为 `@arcships/rutis` 和 `@arcships/rutis-runtime`。旧包用户需要迁移依赖、导入路径、feature 和生成绑定，详见[升级指南](../migration-0.6-to-0.7.md)。所有宿主与语言运行时应一起升级。

包版本不等于协议版本：本地会话仍使用协议 2，带 endpoint 身份的会话使用协议 3；本次版本统一不修改插件 API 标记。基于新内核重新构建的 dylib SDK 身份会变化，必须配套重建宿主和插件。

`rutis-host` 和本地语言运行时支持 Linux / macOS；Windows 用户使用 WSL。Windows 原生 dylib 支持不代表原生 Windows host 已可用。Node 要求 24+，Python 要求 3.12+。

## 开始使用（发布后）

```bash
cargo add rutis@0.7
npx @arcships/rutis-host@0.7.0 new greeter --lang node
uvx --from rutis-host==0.7.0 rutis-host new greeter-py --lang python
```
