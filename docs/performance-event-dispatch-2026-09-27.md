# #62 / #63 事件派发性能样本

日期：2026-09-27。实现分支：`feat/event-keys-and-sync-dispatch`，rutis 0.4.0；旧版基线为 main `603f8220b049c6ad26e82f258fd72f214b8575fe`（0.3.0）。

环境：Linux x86_64，Intel Core Ultra X7 358H，rustc 1.98.1，release 默认优化，Tokio 两个工作线程。以下样本将进程固定到 CPU 0；没有固定 CPU 频率，也没有统计置信区间，不能把几 ns 的差异当成跨机器的结论。

## 运行

```sh
# 本分支接口：普通同步监听器、同步 waterfall、前缀数量变化。
taskset -c 0 cargo bench -p rutis --offline --bench events

# 同一二进制同时链接新旧实现，使用完全相同的 keyed 接口和依赖。
RUTIS_BENCH_CPU=0 bash tools/compare-event-dispatch.sh
```

`taskset` / `RUTIS_BENCH_CPU` 是 Linux 的可选 CPU 绑定；省略后也可以运行。依赖需预先在 Cargo 缓存中。`RUTIS_BENCH_ITERATIONS` 可调整第一个基准的迭代次数，默认 100000，先预热 1000 次。

新旧对比由 [探针](probes/compare-exact-dispatch.rs) 执行：每个监听器数量取七轮、每轮 500000 次派发的中位数，新旧执行顺序交替。使用保留的 `serial_keyed` / `on_keyed` 包装是为了让两版测试代码一致，不推荐新业务继续使用弃用入口。

## 同步派发

监听器都是最小空回调：bail 返回 None，waterfall 调用 next；终点返回 u64。以下为单次基准的平均 ns/op。

| 精确监听器数量 | bail_sync | waterfall_sync |
| --- | ---: | ---: |
| 0 | 412.8 | 420.5 |
| 1 | 475.0 | 543.8 |
| 8 | 971.8 | 1085.2 |
| 64 | 4345.7 | 5248.2 |

实例键的无监听器 waterfall_sync 为 458.6 ns/op。空链没有 future / spawn，也不装箱终点结果，但仍需要关闭 / 代次检查、线程重入保护和 fiber 在途登记。

## 前缀订阅

静态键 `room/hit` 有一份精确异步监听器；存在前缀时，第一份匹配 `room/`，其余都不匹配。所有回调返回 None。这里没有 emit 排队或业务 IO。

| 前缀注册数量 | serial ns/op |
| --- | ---: |
| 0 | 94.1 |
| 1 | 568.7 |
| 8 | 563.2 |
| 64 | 702.6 |
| 1024 | 2309.9 |

前缀派发包含扫描、快照合并、模式命中计数和卸载等待保护；只对命中的订阅检查 owner 存活。少量前缀的主要成本是生命周期保护，而非字符串比较。首版使用线性扫描；需要更多吞吐场景的数据后，再在 #43 中决定是否增加索引或缓存。

## 无模式时的新旧精确派发

下表使用同一动态名字、同一二进制中的两版 serial_keyed，没有模式、观察器或业务回调工作。七轮中位数（ns/op）：

| 精确监听器数量 | 0.3.0 | 0.4.0 | 差异 |
| --- | ---: | ---: | ---: |
| 0 | 55.2 | 58.5 | +5.9%（+3.3 ns） |
| 1 | 112.6 | 97.8 | -13.1% |
| 8 | 273.3 | 262.7 | -3.9% |
| 64 | 1589.7 | 1605.5 | +1.0% |

实现中避免给精确订阅增加原子计数，并将诊断元数据移出常用回调字段；模式选取与实际调用才计数。异步适配器在 future 内调用用户监听器，因此保留原先一次轮询 panic 捕获，避免重复捕获的开销。空链仍多出总线身份校验与模式检查；表中有正负差异，不能宣称所有路径“完全没有性能回退”。这些是代表性本机样本，不是硬性 CI 门槛。

本批没有完成 #43 的服务读取、装载 / 驱逐、并发吞吐和 emit 积压基准，也没有引入背压策略。既有同键 emit 保序、跨键并发和等待取消语义由回归测试确认。
