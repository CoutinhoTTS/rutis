# rutis / Cordis 跨进程挂载：组合设计

依据：[需求](requirements-protocol-plugins.md)。基准：rutis `2e564e3`、Cordis `4.0.1`。状态：组合方案提案；尚未实现，也未获得修改框架内核的授权。

**一个会话连接两个真实框架。服务读取取得对象；方法、属性、回调、事件监听和迭代都操作这些对象；原生依赖与 effect 决定可用性和清理。** 接入生成的是上述操作的绑定，不是另一套插件框架。

本设计确定各机制组合时采用的规则、所需框架扩展接口和验收流程。§9 对现有约束冲突作出明确判断，不再把它们写成“以后验证”。这些判断不等于获准缩小需求。

## 1. 同一套身份与所有者

```text
应用配置包 / 原入口 / 配置 / 运行位置 / 依赖连接
                         |
                     自动生成绑定
                         |
       Rust 应用或插件                    TS 应用或插件
              |                                 |
        真实 rutis                        真实 Cordis
              |                                 |
       原生接入 + 绑定 <====== 双向会话 ======> 绑定 + 原生接入
              |                                 |
          原 Rust 对象                      原 JS 对象
```

不存在另一个业务 host。两端都是应用中的原生框架，适配器是库。首先保持每次独立挂载一个对端运行时，不建设共享进程调度、部署、重启、重连或重试平台。

| 身份 | 表示什么 | 由谁决定 |
| --- | --- | --- |
| 接口 | 类型、成员、参数、同步性、所有权、错误和事件规则 | 原接口，经编译器提取 |
| 服务绑定 | 某作用域中，某个键当前提供什么、是否可用 | 原生注册表和提供者 |
| 对象引用 | 某个具体对象及其原生有效期 | 对象所有者；不会因服务换值而改指向 |
| 注册 | 一次监听、服务提供或其他 effect | 原生注册插件及该次激活 |
| 调用 | 一次操作及其嵌套调用、临时借用 | 原始调用链 |

服务名不是对象身份；对象持有关系不是插件依赖；提供者重新激活不是旧对象复活。注册代次、对象有效期和调用期分别记录，不能共用一个“插件 generation”代替所有生命周期。

跨进程只传生成的接口标识、上述身份和值 / 引用；本地 TypeId、内存地址和两个框架的内部状态枚举不直接作为共同协议。

## 2. 接入时生成什么

### 2.1 选定生成路线

| 步骤 | 方案 |
| --- | --- |
| 选择入口 | 应用指定包和已有 plugin / factory；不要求新增协议入口 |
| TS 分析 | TypeScript 类型检查器读取实际项目、包导出及声明合并 |
| Rust 分析 | 与实际编译器版本匹配的只读语义提取器，在宏展开和类型分析后提取接口及相关注册调用的类型信息 |
| 内部模型 | 记录公共类型、成员、同步性、拥有 / 借用、错误、事件规则及原声明位置 |
| 生成 | 目标语言类型与原生挂载插件、原对象分发器、类型描述表、契约摘要 |
| 校验 | 原语言编译器检查生成代码；两端启动时比对契约，成功后才运行原插件 |

Rust 路线选择编译器语义提取，不再把单文件 syn、cargo metadata 或运行期 TypeId 作为完整接口来源。提取器只读分析结果，不改写原插件控制流；通过构建集成运行，不要求用户单独执行。编译器内部接口不稳定，因此提取器必须按受测工具链发布，不能换一个编译器分析后假称与实际构建一致。这是自动分析完整 Rust 接口的明确维护成本。[编译器回调](https://doc.rust-lang.org/nightly/nightly-rustc/rustc_driver_impl/trait.Callbacks.html)、[Cargo 编译器包装入口](https://doc.rust-lang.org/cargo/reference/config.html#buildrustc-wrapper)。

公共签名的类型闭包与实际具体化的类型参与生成；包内私有实现仍在原进程中。可经公开 trait / 不透明返回接口调用的对象，不要求暴露其私有布局。编译器能看见某个私有定义，不等于外部生成代码具有访问权限。开放泛型或动态类型若无法形成确定的跨语言接口，按 §9 给出具体不兼容结论，不猜测、不漏成员。

静态类型表不固定运行期实例数量。动态服务名、qualifier、对象、监听及提供者代次在运行期登记，并引用已生成的类型描述；新名字不要求重新编译。运行期出现全新的、构建时无法描述的类型，不能假装已给 Rust 消费者生成了它的静态 API。

### 2.2 构建和业务入口

```text
普通安装 / 构建
  -> 解析包、原入口、配置类型、构建选项和连接
  -> 提取接口，生成两端绑定
  -> 编译生成代码及原包
  -> 编译应用，打包对端入口
普通启动
  -> 建立会话并校验契约
  -> 建立原生作用域和双向依赖入口
  -> 用原框架加载原插件
  -> 按原生可用性提供服务
```

生成文件属于构建目录。缓存包含输入源码 / 声明、锁文件、实际工具链、目标、features / cfg 和 TS 配置。应用只声明接入，不逐插件写生成脚本，不维护 IDL 或生成文件。Rust 绑定先于消费者编译，运行期只实例化和注册。

业务继续使用 ctx.require / ctx.get、ctx.xxx、原生事件和 disposer。新生成 Rust 类型可以把外语属性表示成同步访问方法，把外语异常表示成 Result；不因此改写原 Rust 类型已有字段或方法。生成 foreign::Cache 与替换另一个具体 OriginalCache 是不同问题，见 §9。

## 3. 调用、异步结果和反向调用

### 3.1 调用与等待分开

一次调用先执行原语言的“调用函数”操作。它可能立即返回普通值，也可能返回 Promise / Future。等待这个异步结果是另一个操作；不能在通信层无条件 await 所有返回值。

| 操作 | 行为 |
| --- | --- |
| invoke | 执行原方法、属性或闭包，得到普通值、异步结果引用或原异常 |
| await | 按原语言规则驱动 / 等待异步结果，完成本地 Promise / Future |
| release | 放弃一个拥有引用或结束借用；不冒充业务 close |
| 原生控制操作 | 发布 / 撤销服务、登记 / 注销监听、启动 / 清理，使用同一会话 |

JS 函数在所属线程执行到返回，包括 async 函数返回 Promise 前的同步部分。Rust Future 保留构造与 poll 的区别；不能把“创建了 Future”写成“异步函数体已经执行”。返回对象由绑定按来源类型转换：TS Promise 在目标侧仍是异步结果，普通对象不会因为 awaitable 处理而丢失身份。

生成的同步入口等待 invoke 完成。生成的异步入口按本语言规则返回 Promise / Future；涉及原生同步前缀的入口等待的是原调用已返回，随后交还调度器，绝不在同步栈上等待 Promise 最终完成。结果引用使用同一对象缓存，Cordis bail 返回的 Promise 不能被悄悄 await 成它的值。

异步结果的启动也有明确规则：导入为 JS Promise 时立即驱动对应结果，不等用户写 await，否则 emit 忽略 Promise 后 Rust 监听会永远不执行；导入为 Rust Future 时，原 JS Promise 一旦创建就继续原生执行，放弃等待不能取消它。生成器不能一律使用懒执行的 async fn 改变原调用同步前缀；需要时生成普通函数返回 Future，业务仍使用原异步形状。

invoke 返回异步结果引用不代表调用的借用期结束。调用状态连同参数、回调及真实借用保留到原 Promise / Future 完成，或原生取消 / Drop 实际释放它们；取消一个通信等待者不能提前释放。返回借用对象时，有效期继续按原签名关联到拥有者及该借用对象。

### 3.2 执行和顺序

```text
Rust 或 Node 原调用线程               对端原执行环境
        | -------- invoke ----------> |
        | <------- callback --------- |
     执行原回调                        | 等回调的调用结果
        | -------- result ----------> |
        | <--- value / awaitable ---- |
   同步返回 / 把异步等待交还调度器
```

会话使用一个双向 Unix socket、逐行 JSON 帧和带类型的值编码。调用号为“发起端 + 序号”，嵌套操作携带调用链关联。通信线程只收发；JS 闭包不迁到 Worker，Rust 回调遵守原执行器和借用约束。每个方向按接收次序受理调用，但异步完成不阻塞下一条消息，响应按调用号匹配。

同步等待器执行当前调用链所需的反向操作；异步等待回到原调度器。控制消息可以在业务等待中处理。所有会话锁和引用表锁都在调用业务前释放。相关调用链之外的业务不因同步等待被任意重入；后台任务导致的额外调度依赖同样受 §9 的执行边界约束。

这统一覆盖同步方法、属性、立即回调、保存回调、事件监听、next 和迭代。它不承诺推进被同步栈阻塞的完整 Node 事件循环。

## 4. 服务读取、对象和 Context

### 4.1 每次读取解析，每个对象固定

```text
第一次原生读取：服务槽位 -> 对象 A -> 本地代理 A
提供者原地换值：服务槽位 -> 对象 B
第二次原生读取：服务槽位 -> 对象 B -> 本地代理 B
已有代理 A 的后续调用 ----------------> 原对象 A
```

选用读取时解析，不广播每次对象换值，也不让每个方法调用重新查服务名。可用性仍由原生依赖机制传播；对象状态和读取结果由实际操作取得。服务从 A 换成 B 不触发虚假的提供者重启。

读取经过调用方的原生声明、可见性和拦截检查，然后在对应提供方读取视图解析。服务键映射包含接口、原名 / qualifier、实例和 isolate，不只比较字符串。对象缓存按原对象及原生上下文视图区分，不能让不同调用方共享错误的 Cordis 关联 Context。

### 4.2 值、属性和拥有关系

| 内容 | 规则 |
| --- | --- |
| 值 | 按来源类型传递；保留 undefined / null、整数精度、BigInt、浮点特殊值和字节 |
| 对象 / 可变数组 / 函数 | 保留身份；不能因可 JSON 化就转成快照 |
| 属性 | 在归属端执行一次真实读写，保留 this 和原副作用 |
| 往返及再次传递 | 传回归属端恢复原对象；另一端复用同一存活代理，不套多层代理 |
| 拥有引用 | 发出消息前建立接收端持有关系，最后一个本地代理释放后通知归属端 |
| 借用 / FnMut / FnOnce | 保留借用期、独占和单次消费；动态目标语言用运行期检查兑现约束，不改成无限期共享 |
| 弱引用 | 保持弱关系，upgrade 才临时取得拥有引用；协议表不能把原弱边变成永久强根 |
| 迭代 / 流 | 逐次调用原 next / 订阅 / 取消 / 关闭及背压入口，不预先收集全部数据 |

Context 作为参数时传递真实原生 Context 的操作视图；接收插件自身始终拥有本地真实 Context。二者不混同。scope 标识定位视图，派生、isolate、过滤函数、拦截及扩展属性通过原操作处理，不能靠复制一份 Context 字段重建其行为。

被保存的回调是拥有引用，不随首次调用返回而过期；借用回调则随对应调用结束。普通对象引用不自动增加插件依赖，不自动要求另一插件先退出。

借用对象的分发由归属端持有真实借用的调用状态执行；不能把 guard 移到任意通信线程，也不能从编号重新构造一个延长有效期的 Rust 引用。生成的目标类型和归属端保存状态共同兑现有效期，不能只靠一条过期检查消息。

### 4.3 资源与运行时的结束

原生 effect / close 负责业务清理，引用释放负责撤掉持有关系。框架资源属于注册它的原生作用域；独立拥有的对象按自身有效期处理。插件卸载后，原生 Context 可以失活，而一个原本允许独立存活的对象不必立即失效。

对端运行时由会话资源拥有。卸载插件先完成原生清理；仍合法存活的拥有引用可以继续持有会话，不把关闭插件与杀掉进程合并。最后一个挂载和拥有引用释放后结束会话；应用整体关闭或通信故障结束会话时，剩余引用明确失败。失效对象绝不转向新激活实例。

本地 GC、Arc / Weak 和显式清理继续各自工作。适配器只保留活跃原生所有者、在途调用和真实跨端持有需要的强引用，代理缓存为弱缓存。不新增“两个堆共享一个垃圾回收器”的承诺；跨端强引用环仍需要原生 close、注销或弱关系断开。若具体原生用例原本可回收而桥接新增了永久根，应作为兼容缺陷处理，不能用这个边界掩盖泄漏，也不能默认建设分布式 GC。

## 5. 事件如何与调用机制组合

### 5.1 一份登记顺序，原生分发规则

每个连接的事件键及作用域选定一个真实原生总线保存监听顺序，另一端的监听逐个登记进去。监听仍由原注册插件的 effect 拥有。登记确认建立先后关系；并发登记按拥有方提交顺序，prepend 和 once 使用原规则。

```text
原监听 A 登记 -- 完成
远端 B 登记   -- 通过 invoke 登记一个原生监听代理 -- 完成
原监听 C 登记 -- 完成
                          |
                    [ A, B, C ]
                          |
            一次分发，每个监听调用一次
```

不能把远端整条总线包装成一个监听，也不采用两边各广播一次。原生事件扩展接口必须能为一次分发取得带作用域过滤、once 资格和调用期持有的监听快照，随后复用所要求的原生分发算法；不另写一个全局监听调度器。所需接入能力见 §8。

分发入口决定完成语义，事件契约决定参数和结果如何表示。连接只接受能无损映射的契约；同名事件的返回规则不同不代表可以自动合并。

### 5.2 选定的映射规则

| 入口 | 如何调用 | 如何等待 / 短路 |
| --- | --- | --- |
| Cordis emit | 逐个 invoke，保留原 JS 监听同步前缀 | 不 await 返回的 Promise |
| rutis emit | 交原队列，保持同键分发规则 | 原调度器驱动异步监听 |
| parallel | 用原规则启动各监听 | await 相应异步结果，采用调用方原生错误汇总 |
| serial | 按快照逐个调用 | await 后依据该事件契约判断短路 |
| Cordis bail | 同步 invoke | 依据原返回值短路，Promise 自身仍是返回对象 |
| rutis bail_sync | 仅调用同步类别监听 | None 放行，Some(v) 短路，不把异步监听偷偷加入同步表 |
| waterfall | 传递本次原生分发实际创建的 next 引用 | 保留该 next 的有效期、调用次数与返回类型，不生成第二条链 |

内部保留“放行 / 短路及值”，但业务类型由原接口生成。例如 Rust Option<bool> 不能无损变成 Cordis 原始 bool 的短路契约：Some(false) 与 false 的含义不同。生成的外语 Option 类型可以明确表达 Some / None；已经声明为原始 bool 的既有事件不能被静默替换。对这样的连接应给出类型 / 行为不兼容诊断，而不是另定一套真假值规则。

同理，Rust Next 的单次借用可以生成带有效期检查的外语 callable；不能承诺它同时具备 Cordis 多次 next 的能力。事件参数或结果的普通对象、Promise、回调、Context 都复用 §3—§4，不另做事件专用对象系统。

注销先撤掉后续分发资格，已开始的分发按原生快照和 effect 规则收尾。快照扩展接口不统一改写 once 的消费时刻；登记来源的原生 once 包装、作用域和清理语义必须保留，不能在两端各包一次 once。同键重入检查仍属于原框架，不由通信重试或代理缓存决定。

## 6. 依赖、保存引用与关闭不能混成一张图

### 6.1 依赖连接

导出侧是原服务的原生消费者；导入侧在对应本地作用域提供生成绑定。仅当原依赖机制认定可用时发布，撤销时走原生门控。可选读取保持可选，不因协议监听变化就增加必需依赖。

```text
Rust Audit 提供者
  -> 导出 Audit
  -> Node 导入 Audit
  -> 原 Cordis Search 插件
  -> 导出 Search
  -> Rust 导入 Search
  -> 原 rutis 消费者
```

这是同一条依赖链跨过会话两次，不是两套互相等待 Active 的装载器。连接和接入入口先建立，业务依赖再由原框架判定。每个投影的提供者及其激活独立拥有注册，不能把整进程所有服务合成一个必需依赖和清理单位。

保存回调、Cursor 持有 Search、事件的 next 都只形成引用或调用关系。除非原插件声明依赖，不把这些关系加进上述关闭顺序；这是避免桥接凭空制造循环等待的关键。

### 6.2 单向撤销协议

提供者向导入侧发起撤销；导入侧卸载只撤销自己的订阅和注册，不反过来要求原提供者或整个进程退出。原服务依赖边可等待下游必需清理，普通引用释放不等待对端插件 shutdown。

```text
提供者开始撤销
  -> 标记本次绑定不可新获取，保留合法旧引用
  -> 对端开始撤销导入提供者
  -> 原生消费者开始清理
  -> 清理期间仍可调用保留的对象、回调和 close
  -> 下游原生清理完成，返回确认
  -> 完成导出适配器清理
```

先启动清理，再等待需收尾的在途调用。不得先排空调用再执行 disposer，因为 disposer 可能正是解除调用等待的动作。清理期使用已取得的对象，不通过失活 Context 重新 require。

重复撤销加入同一注册代次的完成结果；旧撤销不能删除新注册。会话结束由外层资源所有者统一收尾，单个导出 disposer 不等待整个会话关闭。双方同时卸载时，各自先启动本地原生清理，仍按单向依赖撤销完成确认，不建立“互相等待整进程退出”的边。

原生依赖本来成环、业务 disposer 本来互等，不由协议猜测打破；由投影聚合、双向 shutdown 或错误排空次序新增的环属于实现错误。不得提前伪造完成确认。

### 6.3 故障和代次

断连失败全部在途等待，撤销相关原生注册，完成本地可完成的清理。已发送但未收到结果的调用标明执行结果未知；取消等待不表示对端副作用已撤销。无关插件不退出，没有重放或自动重连。

重新激活产生新的注册代次，旧调用 / 注销不能操作新注册。原生 close 已结束的对象报失效；合法独立存活的旧对象仍指向旧对象，不冒充新服务。业务错误、接口错误、不可用、失效和通信失败分别进入目标语言错误通道。

## 7. 用同一个业务场景检查组合

场景：rutis 提供 Audit；原 Cordis Search 依赖 Audit，返回 Cursor，保存用户回调并广播 page；rutis 消费者使用 Search 和 page。以下是设计要求的组合轨迹，不是已实现测试声明。

| 阶段 | 完整行为 | 约束 |
| --- | --- | --- |
| 构建 | 从原 Search、Audit、Cursor、page 接口生成双向绑定 | 一个类型表覆盖服务、事件载荷和回调，不分别手写协议 |
| 初始化 | 会话及反向 Audit 先接通；原 Search 按 Cordis 依赖启动 | 不等待 Search Active 才建立 Audit |
| 调用 | 消费者取得 Search A，异步 scan 返回 Cursor K | scan 的异步结果与 K 是不同引用 |
| 保存回调 | Search 保存消费者传入的回调，scan 返回后仍能调用 | 持有期由原接口决定，不按调用号结束 |
| 事件 | page 的监听 A、B、C 按原顺序参与；B 可异步调用 Audit | 监听调用、异步等待及反向调用共用会话 |
| 同步操作 | Cursor 的同步属性 / 方法可调用同步回调并返回普通值 | 等的是 invoke，不强行等待异步结果 |
| 换值 | Search 槽位换成 B；新读取拿 B，已有 A、K 保持原对象 | 无换值广播，无方法重定向，无虚假重启 |
| 撤销 Audit | 原依赖链开始关闭 Search，再关闭其必需消费者 | 只有真实依赖决定顺序，保存回调不新增依赖环 |
| 关闭 Cursor | 消费者清理调用 K.close，允许其完成反向操作和解除在途等待 | 清理开始早于排空；对端通信仍可用 |
| 收尾 | 注销监听、释放回调及拥有关系，完成原生清理 | 业务 close、引用释放、会话关闭分别完成 |
| 任意阶段断连 | 失败在途调用，撤销投影，本地清理报告失败 | 无伪成功、无重放、旧引用不转投新实例 |

同一场景反向运行：Cordis 提供依赖、挂载原 rutis 插件，交换两端角色，不另设计一套协议。

## 8. 框架需要提供的最小接入能力

仅有普通 provide / on / effect 不足以承载上述完整模型。方案选择两组局部扩展接口；协议、序列化、进程管理均留在外挂库。下表是待评审的接口契约，不是本轮改核授权，也不是已有 API 的描述。

| 扩展接口 | 必要操作 | 约束 |
| --- | --- | --- |
| 服务接入 | 提供按读取方解析值的绑定；覆盖 get / require；观察选定类型及作用域中的原生注册、可用性和撤销 | 原声明 / 可见性检查仍生效；解析在框架锁外执行；返回实际类型；观察不替代依赖判断 |
| 事件接入 | 对选定事件键路由登记、注销和分发；提供原生监听快照 / 调用资格；允许原生分发算法使用该快照 | 保留原 effect 所有者、过滤、once、重入及在途清理；本地后端有直接入口，避免再次进入路由 |

服务接入用解析绑定取得新对象，因此不要求给每次 ServiceWriter::set 加全局广播。现有 rutis intercept_require_as 不覆盖 get_as，写拦截又发生在提交前，不能冒充这个扩展接口。Cordis 需要同时覆盖属性读取和 reflect.get，不能只安装一个 accessor 就宣称原生读取已完整接入。

事件扩展接口只处理明确连接的键和作用域，其他事件继续原路径。若归属选在 rutis，Rust 监听留在原表，TS 监听逐个进入该表；Cordis 的原生入口统一路由。若归属选在 Cordis，反向相同。不读取私有 Hook 后复制出第二套总线，也不依赖事后 dispatch 观察修改返回值。

原生生命周期不新增另一套状态机。沿用原生消费者、提供者和组合 effect；rutis 逆序清理与 Cordis 并发 effects 的差异在适配器自身的组合 effect 中处理，不重排原业务 effects。

核对依据：[rutis 读取](../crates/rutis/src/ctx.rs)、[服务写入与拦截](../crates/rutis/src/intercept.rs)、[注册表](../crates/rutis/src/registry.rs)、[事件](../crates/rutis/src/bus.rs)、[effect](../crates/rutis/src/effect.rs)；Cordis 4.0.1 的 `src/reflect.ts`、`src/events.ts`、`src/fiber.ts`。

## 9. 约束冲突的结论与最小取舍

以下不是普通待办，不能通过“再写一个代理”消除。需求保持原文；若采用取舍，须明确确认对应差异。

| 组合 | 结论 | 本方案建议 |
| --- | --- | --- |
| 现有公开 API 完全不变 + 覆盖所有原生服务读取及事件入口 | 现有接口不能承载 §4—§6 的完整路径；普通注册和观察接口不等于接管入口 | 评审 §8 两组局部扩展接口，协议逻辑仍全部外挂；不建设通用内核重写 |
| 原同步签名 + 必须等待一个依赖被阻塞原线程的异步结果 + 不改运行时 | 等待成环；区分 invoke / await 能保留正常异步接口，但不能让此组合完成 | 保留同步调用及同步反向调用；这类接口需要异步边界。未经确认不改签名，也不宣称已支持 |
| 任意原生具体类型 / 事件契约可无损互换 + 原消费接口完全不变 | 类型或语义确有不兼容时，不存在通用无损转换 | 生成另一语言对原接口的绑定；既有不同契约的连接报明确不兼容，不伪造同名类型或改变短路语义 |

同步冲突的具体例子：Node 同步调用 Rust；Rust 等待传入的异步回调；回调等待 Node 原线程的 timer；Node 原线程却要等 Rust 返回才可继续。通信 Worker 不能执行原闭包，libuv uv_run 不能从回调中重入。普通嵌套同步回调、异步 scan、emit 启动异步监听都不需要这个非法等待，不能把它们一并排除。[Node 线程通信](https://nodejs.org/api/worker_threads.html#worker_threadsreceivemessageonportport)、[libuv 循环规则](https://docs.libuv.org/en/v1.x/loop.html#c.uv_run)。

具体类型冲突只适用于实际替换场景：生成 foreign::Cache 给 Rust 使用，不要求它伪装为别的 crate 的 OriginalCache；原 Rust 插件留在 Rust 中供 TS 使用，也不要求替换原类型。但若连接明确要求给已有 OriginalCache 注入另一具体代理，或给无错误通道的方法增加通信失败而又禁止改变形状，必须如实指出差异。[Rust 类型存储](../crates/rutis/src/registry.rs)、[字段访问](https://doc.rust-lang.org/reference/expressions/field-expr.html)。

按 §8 扩展接入能力能解决入口缺失；它不能解决线程等待环或不兼容类型。不能把授权一处小改动说成全部“任意插件”目标因此成立。

## 10. 验收与现有实现的关系

| 验收 | 判定方式 |
| --- | --- |
| 原生对照 | 同一普通插件先记录本地结果、调用顺序、对象身份和清理轨迹，再作双向跨进程对照；不比较通信耗时 |
| 自动接入 | 干净应用按包配置后正常构建启动，无手工生成；模块、宏、实际构建条件、类型变化及契约不匹配有覆盖 |
| 组合主线 | §7 全部阶段在两种应用方向成立，不能只验孤立方法 |
| 特殊语义 | emit 同步前缀、bail 返回 Promise、Some(false)、next 次数、once 嵌套分发、分发中注销、isolate / 过滤 |
| 所有权 | 旧 A / 新 B、对象往返、保存回调、借用结束、独立对象存活、弱引用、提前关闭流 |
| 生命周期 | 可选依赖不变必需；关闭解除在途等待；同时卸载无新增环；旧消息不影响新注册；断连无重放 |
| 边界诚实性 | §9 的真实冲突不能计为已兼容；拒绝用例不等于完成任意插件目标 |

[PR #73](https://github.com/arcships/rutis/pull/73) 仍是[双向值方法切片](../examples/native-mount/README.md)。可复用原插件示例、原生注册及编译检查；服务名调用须改为固定对象引用，调用器须分清 invoke / await 并支持反向调用，清理须先开始再排空。不能据当前代码已经存在而反推需求或保留错误机制。

历史 [#66](https://github.com/arcships/rutis/issues/66)—[#70](https://github.com/arcships/rutis/issues/70) 中仅异步事件、仅调用期回调、排除 waterfall / 流及人工维护接口的限定已被最新需求覆盖。本设计不恢复这些旧范围，也不新增垃圾回收、部署或容错平台。
